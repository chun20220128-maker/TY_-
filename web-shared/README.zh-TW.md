# 鑽探工作台：公司網頁版部署預覽

這是可部署的網頁版，尚未在你的 Cloudflare 帳號上線。工程師日後直接用專用網址操作，不需要 Windows 安裝檔，也不依賴出現 WinError 14001 的內附視窗元件。

## 已完成的操作方式

- 保留 01 規劃、02 估價、03 契約、04 請款與原有匯出功能。部署包中的格式範本已清除原填寫數量、金額與工程資料。
- 共用歷史單價儲存在 Cloudflare D1，所有持有有效連結的工程師使用同一份；部署包不內含真實價格；管理者完成上線後，從受保護的頁面一次批次匯入原有 14 案／322 筆 CSV。
- 新增或修正歷史 CSV 會寫入共用資料庫；相同紀錄只更新，不重複新增。
- 若其他工程師已更新單價，本次舊版本匯入會停止並提醒重新確認，不會默默覆蓋。
- 規劃、估價、契約、請款的本案作業只暫存在工程師目前的畫面，不寫入共用資料庫。
- 專案需要自行「匯出備份」。關閉分頁、重新整理或結束作業前請先備份；下次開啟為空白新專案，可匯入備份接續。

## 專用連結如何保護

完整連結包含一段隨機存取憑證。瀏覽器使用它通過伺服器驗證，沒有有效憑證就不能讀取工作台頁面或共用單價 API。這不只是隱藏網址，也不靠搜尋引擎排除當作權限控管。

憑證由管理者在自己瀏覽器中產生；部署 ZIP 不含任何預設密碼或有效憑證。伺服器只保存驗證雜湊。連結的片段不會出現在一般 HTTP 網址或 Referer 中；驗證資料透過 HTTPS Authorization 傳送。

**持有者可以轉傳完整連結。** 本版不驗證工程師本人，不能單獨撤銷某一個人的權限；需要時由管理者更換整組連結。系統只接受固定正式網站的資料 API，舊版部署的預覽網址不能拿來繞過換鑰後的驗證。若將來需要指定帳號與個別停權，需增加登入功能。

## 管理者一次性上線步驟

工程師不需要完成以下步驟；只由管理者操作一次。

### 1. 建立 Cloudflare 帳號

開啟 https://dash.cloudflare.com/sign-up ，註冊並完成信箱驗證。先使用免費方案即可試行；免費方案有用量與容量限制，增加使用量時再評估是否升級。不需要另外購買網域。

不要在對話中提供帳號密碼。

### 2. 建立共用資料庫

在 Cloudflare 的儲存／資料庫服務中選擇 **D1 SQL Database**，建立一個資料庫，例如 `drilling-history`。不需要手動貼 SQL 或重新整理 14 案資料。

### 3. 上傳管理者部署包

下載 `DrillingWorkbench_Company_Web_Deploy.zip`。這是管理者上傳用的站台包，**不是工程師要安裝的程式**。

依 Cloudflare 官方 Direct Upload 流程：

1. 進入 **Workers & Pages**。
2. 選擇 **Create application → Get started → Drag and drop your files**（Pages）。
3. 輸入專案名稱並上傳上述 ZIP。
4. 按 **Deploy site／Save and Deploy**。

Cloudflare 會提供固定的 `https://實際專案名稱.pages.dev` 網址。若名稱已被使用，另取名稱即可；以畫面顯示的固定正式網址為準，不要用帶版本編號的預覽網址。

本包使用 Cloudflare Pages 支援的 `_worker.js` 進階模式，沒有要你另外安裝 Node.js 或編譯工具。

### 4. 綁定資料庫

在此 Pages 專案的 **Settings／設定 → Bindings／繫結** 加入 **D1 database**：

| 欄位 | 填寫內容 |
|---|---|
| 變數名稱 | `DB` |
| 資料庫 | 剛建立的 `drilling-history` |
| 環境 | Production／正式環境 |

### 5. 產生專用連結並設定驗證值

在固定網站網址後面加上 `/setup` 開啟。例如實際固定網址後加 `/setup`；這裡不提供尚未建立的假網址。

1. 按「產生專用連結與設定值」。
2. 按「下載連結備份」，將完整連結妥善保存在自己的電腦。
3. 到 Pages 專案 **Settings → Variables and Secrets／變數與密鑰**。
4. 新增名稱 `ACCESS_TOKEN_SHA256`，值貼入設定頁顯示的驗證雜湊。請選正式環境。

這份管理者連結備份**不要上傳到公開儲存庫或網站**。

### 6. 再部署一次並驗收

回到 Pages 的部署畫面，選擇 **Create a new deployment → Production**，再次上傳同一份站台 ZIP。這會讓資料庫綁定與驗證值套用到新部署。

開啟剛保存的完整專用連結。第一次讀取共用單價時，系統會自動建立空白資料表。請在「歷史參考單價」一次選取原有 14 份 CSV 匯入，確認共 14 案／322 筆後再分享連結。資料只傳到你自己的受保護網站，不放在公開部署檔內。之後新建專案不會清除共用單價。

先用兩個不同瀏覽器確認：

- 沒有完整連結時，不能進入工作台。
- 工程師甲匯入一筆測試歷史 CSV，工程師乙開啟歷史單價即可看到。
- 甲、乙填寫不同的工程名稱，彼此不影響。
- 專案可匯出及匯入備份；本案內容不會出現在共用單價中。

完成驗收後，再把完整專用連結給工程師。

## 備份與維護

- 歷史單價每次有變更，會保留更新前的資料快照，最多最近 30 次。也建議管理者定期按「匯出歷史參考單價」保存在公司備份位置。
- D1 是公司的共用資料庫；請勿為了部署新版而刪除或換成另一個空資料庫。
- 專案備份由工程師自行管理，雲端不自動保存本案作業。專案備份中的參考價格不會自動寫入公司共用資料庫，價格請另由歷史 CSV 匯入。
- 遺失或需要更換專用連結時，先清除驗證雜湊並重新部署，再從 `/setup` 產生新連結及驗證值；共用資料庫可維持原本那一個。

## 驗證範圍

已通過本機 SQLite 支援的 D1 API 模擬測試，以及實際 Chromium 的雙工程師瀏覽器測試：有效連結驗證、拒絕私有資產直讀與跨來源操作、14 案合成測試資料、增修單價不重複、同時匯入的版本衝突、專案不送往伺服器、手動備份還原及重新開啟空白專案。

**尚未在你的 Cloudflare 帳號部署或完成正式網址驗收。** 管理者完成上述設定後，仍需進行上線驗收。

官方參考：https://developers.cloudflare.com/pages/get-started/direct-upload/

若原本單機版後續新增過歷史單價，請從原版匯出歷史 CSV，再於網頁版匯入；新網站無法自行讀取工程師電腦上的 SQLite 檔案。
